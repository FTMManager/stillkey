# 06 · Milestones and acceptance tests

Each milestone ends with one command that passes or fails: `cargo xtask test <name>`. Tests boot the real image in QEMU, read the serial log, and check QEMU's exit code.

A milestone is accepted when its tests pass **20 times in a row on a clean checkout** (`cargo xtask test <name> --repeat 20`), in both build profiles and on every usable accelerator, because boot bugs are often intermittent (D-W-5). The usable accelerators are `--accel kvm` and `--accel tcg` when `/dev/kvm` can be opened, and `--accel tcg` alone otherwise; the test summary then says `accel=tcg only`. `--repeat` applies to the boot tests, in which the guest ends the VM, and from Milestone 2 to the scenario tests, which the harness ends; checks that run only on the host, and the tests that take a picture of the screen (`m1-screen`, `m2-screen`), run once per invocation.

The security property each milestone demonstrates is in [04 §9](04-security-and-permissions.md#9-what-each-milestone-demonstrates). Every property claimed there has a pass criterion here. The criteria tables of Milestones 2–4 name, in the column "Shows", the invariant (I1–I9, [04 §2](04-security-and-permissions.md#2-invariants)) or the decision each criterion is evidence for.

Milestones 1–4 run only in the VM. No step before Milestone 5 touches a physical disk, a firmware setting, Secure Boot, BitLocker or the Windows boot configuration.

**Lines that tests read.** A test considers only lines that start at column 0 with `SK:` or, from Milestone 3, with `AUDIT `, so that wording elsewhere can change freely.

- Loader and kernel lines have the form `SK:<COMPONENT>:<EVENT> key=value …` ([07 §7](07-milestone-1-spec.md#7-boot-behaviour-and-expected-serial-output)). Milestones 2–4 depend on two kernel lines in particular: `SK:KERNEL:SPAWN pid=<n> name=<s> class=<s> handles=<n>` and `SK:KERNEL:CRASH pid=<n> name=<s> vector=<n> addr=<hex> rip=<hex> error=<hex>`.
- Audit entries are mirrored to the serial log as `AUDIT seq=<n> t=<ms> kind=<asked|granted|denied|revoked|released|crashed|ended> pid=<n> name=<s> grant=<id|-> object="<label>" actor=<s> [reason=<s>]` ([04 §8](04-security-and-permissions.md#8-audit-log)). The actors are `prompt`, `shell`, `workbench`, `init`, `permd`, `policy:<name>` and `kernel`.
- Text from a ring-3 process reaches the log only through `debug_write`. The kernel writes it as one line, `SK:APP:OUT pid=<n> name=<name> | <text>`, with the backslash and every byte outside 0x20–0x7E shown as `\xNN` (system-call table in [03 §5](03-kernel-and-interfaces.md#5-minimum-interfaces-by-concern)). App text can therefore never start a line, and an app cannot forge an `SK:` or `AUDIT` line. Output above the rate limit is dropped and reported as `SK:APP:DROPPED pid=<n> bytes=<n>`.
- The trusted services print three markers of their own: `SK:PERMD:POLICY name=<s>`, `SK:DESKTOP:PROMPT app=<s> path=<s> action=<s>` and `SK:WORKBENCH:PROBE ok=<n>`. They are ring-3 output like any other, so each arrives as the text of an `SK:APP:OUT` line. A test accepts one only when the `pid=` that the kernel wrote on that line belongs to the System-class process of that name, according to its `SK:KERNEL:SPAWN` line.

**How a run ends.** A kernel panic ends QEMU with status 37 and a loader refusal with status 35 ([07 §6](07-milestone-1-spec.md#6-vm-launch-command-and-exit-codes)); either fails a test unless its criterion expects it. From Milestone 2 a healthy system keeps running, so the harness follows the serial log and stops QEMU once every line the scenario requires has appeared. A forbidden line, or the time limit, fails the run.
